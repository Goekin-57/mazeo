# MAZEO V4.1 — Refonte UX/UI, ergonomie et gameplay

Amélioration de la V4 (aucune mécanique, carte ni record modifiés). Chaque changement ci-dessous
répond à un problème constaté sur les captures des tests V4 (360 × 640 à 1280 × 800).

## 1. Audit des écrans (V4)

| Écran | Problèmes constatés | Correction V4.1 |
|---|---|---|
| Tous | 45 textes entre 26 et 32 unités, soit ≈ 9–11 px réels sur un téléphone de 360 px : trop petits | Échelle typographique centralisée, minimum 12,5 px (légendes), 15 px (texte), 17 px (boutons) |
| Tous | 5 formes de boutons ; deux boutons orange côte à côte (même importance) | Un seul composant `uiButton` : principal (orange, 56 px), secondaire (crème bordé, 48 px), icône (zone ≥ 48 px) ; un seul principal par écran |
| Accueil | Navigation sans état actif, icônes et libellés de tailles variables ; bouton « CONTINUER » proposé alors que le chapitre était terminé | Barre de navigation commune avec capsule active et pastilles ; libellé du bouton selon la progression (JOUER / CONTINUER / DÉFI DU JOUR / REJOUER LE CHAPITRE) |
| Jeu | Bandeau haut de 190 unités + puce séparée ; son, annuler, recommencer et pause au même niveau visuel ; plateau petit | Bandeau compact (retour, nom court, objectif, pause) ; son déplacé dans Pause ; Annuler / Recommencer en secondaires en bas ; plateau agrandi (case jusqu'à 270 unités) |
| Jeu | Sortie parfois discrète (maison/portail parmi le décor), bulle « 0/2 » ambiguë | Repère de destination flottant (drapeau, ou cadenas tant qu'une condition manque) + halo au sol ; animation et son de validation quand la sortie s'active |
| Jeu | Tracé prévu = simple ligne ; aucun retour quand le doigt bute sur une haie | Cases prévues surlignées + flèche de direction sur chaque case ; croix brève sur la case refusée ; tolérance tactile (centre de case) ; gestes rapides en diagonale résolus |
| Jeu | Pause = panneau dans la scène, le niveau continuait de s'animer | Scène Pause superposée : le niveau est réellement suspendu (`scene.pause`) |
| Bloqué | Annuler / Recommencer dans le message ET en bas | Un seul panneau d'actions qui remplace les commandes du bas |
| Victoire | Panneau haut (≈ 700 unités) avec trois lignes de critères redondantes | Feuille compacte : « Bravo ! », étoiles, cases/optimal/record sur une ligne, récompense, NIVEAU SUIVANT (principal, large) + Rejouer |
| Défis | Défi du jour et hebdomadaire de poids équivalent ; deux boutons orange ; petits boutons « Jouer » (≈ 35 px) ; grande carte vide « Défis précédents » | Défi du jour dominant ; TENTATIVE CLASSÉE (principal) + Entraînement (secondaire) avec leur différence en une ligne ; boutons hebdomadaires uniformes de 48 px ; historique repliable, masqué s'il est vide |
| Collection | Cartes sans état clair ; « Nouveau » permanent | Sections Tenues / Compagnons / Décorations / Badges ; état ÉQUIPÉ / ÉQUIPER / VERROUILLÉ ; « Nouveau » visible une seule fois ; Bourgeon réagit à l'équipement |
| Communauté | Grand panneau presque vide, classements trop hauts | 4 statistiques réelles ; carte « Défier un ami » mise en avant (aperçu + COPIER LE LIEN) ; classements réduits à une carte d'information |
| Carnet de voyage | Six médaillons de même poids sur une carte | Chapitre actif en grande carte (illustration, progression, étoiles, état) ; chapitres futurs en cartes compactes atténuées ; tracé du voyage ; courte animation au déblocage |
| Navigation | Chaque écran avait seulement « retour » | Navigation basse commune sur les écrans de menu (pas pendant un niveau, pour l'immersion) |

## 2. Design system (`src/ui/theme.ts`, `src/ui/components.ts`)

L'écran logique fait 1080 unités de large, conçu pour 360 px CSS : 1 px ≈ 3 unités (`px()`).

- **Couleurs** : principal orange, surfaces crème, encre et encre douce (contraste ≥ 4,5:1), succès, accent turquoise, verrouillé.
- **Typographie** : display 30 · titre 22 · intertitre 18 · texte 15 · étiquette 14 · légende 12,5 (px CSS).
- **Espacements** (multiples de 4) : marge latérale 18 · entre actions 12 · entre sections 24 · intérieur de carte 16.
- **Rayons, ombres, durées** : carte 18, bouton 28 ; ombre douce unique ; appui 70 ms, relâche 140 ms, transitions d'écran 180–220 ms.
- **Tailles tactiles** : principal 56 px, secondaire 48 px, icône ≥ 48 px de zone tactile, interrupteurs ≥ 48 px.
- **Composants** : `uiButton`, `cardBg`, `chip`, `navBar`, `statTile`, `enableScroll`, `fixToScreen`, écran type (`setupScreen`).

## 3. Gameplay : audit des six niveaux

Cartes **inchangées** (aucun record invalidé). Vérifications : départ toujours visible (Bourgeon
dessus + anneau) ; sortie désormais signalée par un repère dédié ; objectifs entourés d'un anneau
au sol ; décisions mesurées en V4 (taux de réussite au hasard 100 → 43 → 20 → 22 → 14 → ≈ 4 %).
Intro courte au premier passage de chaque niveau (désactivable dans les paramètres).

## 4. Bugs trouvés et corrigés pendant la V4.1

- **Navigation qui volait les touches** après défilement : les zones tactiles des enfants d'un
  conteneur fixe suivaient la caméra. Corrigé par `fixToScreen` (enfants fixés récursivement).
- Bouton Recommencer actif alors qu'il n'y a rien à recommencer : désormais désactivé.
- Panneau « Défi reçu » (lien partagé) : « Plus tard » chevauchait « Entraînement » sur 360 et 390 px
  de large. Espacement du panneau corrigé.
- Contenu défilant visible sous la barre de navigation (tablette, ordinateur) : voile opaque sous la barre.
- Textes trop longs dans Défis, Communauté et Carnet de voyage : raccourcis ou renvoyés à la ligne.

## 5. Vérifications

- `npm test` : tests unitaires du moteur, du solveur, de la sauvegarde, du calendrier et des scores.
- `npm run validate` : les 6 niveaux et les 16 défis sont résolus par le solveur.
- `npm run e2e` : 7 parcours Playwright exécutés sur 5 formats (360 × 800, 390 × 844, 412 × 915,
  768 × 1024, 1280 × 800), avec captures dans `tests/shots/e2e/` relues à la main.
- Non vérifié ici : fluidité réelle à 60 i/s (le bac à sable n'a pas de GPU), Safari iOS.
